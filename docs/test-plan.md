# Перевірки TiltTrainer

## Межі перевірки

ЛР1 перевіряє платформу та її відтворювану збірку. Таблиця нижче є майбутнім приймальним планом ЛР2; жоден тест датчиків не виконано. Проектні пороги з [PRD](PRD.md) треба перевірити на шумі та змінювати лише разом із вимогами й очікуваними результатами.

Для тестів нахилу Wokwi задає компоненти прискорення в g, а не кут моделі. За еталона `(0,0,1)` використовуємо `(sin θ,0,cos θ)`; для нахилу навколо іншої осі `(0,sin θ,cos θ)`. `rotationX/Y/Z` залишаємо 0 для статичних поз. Наприклад, 30° відповідає `(0.5,0,0.8660254)`. Значення і одиниці підтверджує [документація Wokwi MPU6050](https://docs.wokwi.com/parts/wokwi-mpu6050#units).

## Перевірки платформи ЛР1

1. Виконати `docker --version`, `make clean`, `make build`; перевірити нульові exit codes і наявність ELF/HEX/BIN.
2. Повторити чисту збірку, порівняти SHA256 усіх трьох форматів, а не лише BIN. Зберегти час запуску, версії інструментів та image ID в логах.
3. У Ubuntu 24.04 повторити чисту Docker-збірку. Порівняти версії GCC/binutils/newlib та SHA256. Однаковий Dockerfile сам по собі не гарантує однакових пакетів у різних датах або архітектурах.
4. Після реального запуску `Wokwi: Start Simulator` перевірити `STM32C031C6 ready`, послідовні `tick` і перемикання PA5 приблизно раз на секунду. UART-запис і запис екрана є доказом виконання, вихідні рядки у C-файлі таким доказом не є.

Результати збірок зберігаються в `docs/verification/`. Стан симуляції треба зазначати окремо. Приймальні тести датчиків починаються після їх реалізації в ЛР2.
