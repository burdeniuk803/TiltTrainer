# Результати збірок TiltTrainer

Перевірено 04.10.2026. Дати комітів не є часом запуску перевірок; логи зберігають фактичний час у UTC.

| Перевірка | Результат | Доказ |
|---|---|---|
| Mac, чиста збірка 1 | `make clean`, `make build`, exit 0, ELF/HEX/BIN створено | [macos-build-1.log](macos-build-1.log), [SHA256](macos-build-1.sha256) |
| Mac, чиста збірка 2 | exit 0; усі три формати побайтно збігаються зі збіркою 1 | [macos-build-2.log](macos-build-2.log), [SHA256](macos-build-2.sha256) |
| Ubuntu 24.04, чиста Docker-збірка | exit 0; HEX/BIN збігаються з Mac, повний ELF має відмінність debug-рядка | [ubuntu-build.log](ubuntu-build.log), [SHA256](ubuntu-build.sha256) |
| Аналіз ELF Mac/Ubuntu | Єдина відмінна секція `.debug_str`; усі `PT_LOAD`, entry point і flags однакові | [elf-comparison.json](elf-comparison.json) |
| Wokwi, UART ready/tick, LED | Реальний запуск ще не підтверджено | Потрібні власні запис UART і запис екрана |
| MPU6050, ADC, кнопка калібрування | Не реалізовано, не тестувалося | План ЛР2 у [PRD](../PRD.md) та [test-plan.md](../test-plan.md) |

Для читабельності логів задано `MAKEFLAGS=--no-print-directory` і `BUILDKIT_PROGRESS=plain`. Це прибирає службові рядки входу в каталог і задає текстовий Docker-вивід; компіляційні прапорці та прошивку не змінено. У копіях build-логів персональні шляхи bind mount замінено на `<project>`; вивід компілятора, час і хеші не редаговано. Версії Docker, GCC, пакетів та image ID записано в кожному build-лозі.

## SHA256 артефактів

| Артефакт | Mac, обидва запуски | Ubuntu |
|---|---|---|
| ELF | `0f7b87f63097adfc290c57ea018a65e5a05da061aaa48fd520c14fbfe05f85da` | `0f9a6dd253dafdc57692ef229aaa3e994e70949ead8f82103967e4e85efa1ff7` |
| HEX | `20c68952fd3c7ab6640f8ca53935729d6ca2c54d55dbba98597a92c2e0248415` | Такий самий |
| BIN | `c21e312881deefbec24a06e9808d3651367530ac8ea930d3b37cc011daa7f7df` | Такий самий |

Mac використовував Linux ARM64-образ, Ubuntu Linux AMD64. Пакети збіглися: GCC `15:10.3-2021.07-4`, binutils `2.38-3ubuntu1+15build1`, newlib `3.3.0-1.3`, make `4.3-4.1build1`.

ELF має entry point `0x08003271`. Порівняно SHA256 кожної секції та вміст, адреси, розміри і прапорці всіх сегментів `PT_LOAD`. Єдина відмінна секція `.debug_str` має в обох файлах 17329 байтів. Її рядки відрізняються тільки шляхом збірки бібліотеки libgcc: фрагмент `gcc-arm-none-eabi-A9GHXF` на Mac проти `gcc-arm-none-eabi-hYfgK4` на Ubuntu. Після заміни цього шляху однаковою міткою дані `.debug_str` збігаються. Це аналіз копій артефактів, вихідні ELF не змінювалися.

`arm-none-eabi-size` в усіх збірках показав text 13464, data 120, bss 1808 байтів. Результат підтверджує відтворюваність повного ELF між двома чистими Mac-збірками та виконуваного образу між двома архітектурами контейнера. Побайтної рівності повного ELF між Mac і Ubuntu немає.

Dockerfile не фіксує digest базового образу й точні версії apt-пакетів. Тому ці результати стосуються записаних запусків, а не гарантії будь-якої майбутньої збірки. Повторний запуск з іншим набором пакетів треба перевіряти окремо.

Логи підтверджують компіляцію та створення файлів. Вони не підтверджують роботу периферії або симуляцію. Докази симуляції, PDF-звіт залишаються наступними кроками.
